# e-api

Generic **e-stack** API service template: Litestar + Granian + msgspec on uv, Rust-backed tooling end to end.
The common modules (`infra/`, `ops/`, `ports/`, `providers/`, `engines/`, `processors/`) live once in `../common` and are materialized here by `make common`.

##### LAYOUT #####

```
src/e_api/             # the service: api/ (lifespan, routers, security), mcp/ (the MCP door), models/, websockets/
src/e_api/infra/       # GENERATED by `make common` from projects/python/common — edit there, never here
src/e_api/ops/         # GENERATED by `make common` from projects/python/common — edit there, never here
src/e_api/ports/       # GENERATED by `make common` from projects/python/common — edit there, never here
src/e_api/providers/   # GENERATED by `make common` from projects/python/common — edit there, never here
src/e_api/engines/     # GENERATED by `make common` from projects/python/common — edit there, never here
src/e_api/processors/  # GENERATED by `make common` from projects/python/common — edit there, never here
tests/unit/            # mirrors src, import-mode=importlib; no service in the default run (`tests/conftest.py` fakes them all)
tests/benchmark/       # the load no single module owns: the whole app under concurrent traffic (`make stress`)
tests/support/         # the fakes the mirror shares (a scripted psqlpy pool, the accounts' store, the MCP client) — redis rides fakeredis
Dockerfile             # two-stage: builder (uv) + deploy (python-slim, non-root)
compose.yml            # single e-api service, :8000
```

##### TAXONOMY #####

Providers sit by capability — `providers/<drivers|adapters>/<capability>/<name>.py` (`e_api.providers.drivers.store.redis`,
`e_api.providers.drivers.http.wreq`, `e_api.providers.drivers.database.psqlpy`) — and the settings mirror that tree:
`st.providers.drivers.store.redis.url`, `st.app.port`. Every exception descends from `e_api.infra.errors.CoreError`; the
service's own live in `e_api` and stay out of that tree. Env variable names are unchanged (`REDIS_URL`, `POSTGRES_DSN`).

##### USAGE #####

```bash
make install        # materialize infra + sync deps
make run            # python -m e_api
make check          # lint + type + arch + validate + infra-drift + test
make integration    # the tests marked `integration` (a real service); out of check, test and cov
make stress         # soak concurrent-load tests
make up             # docker compose up
```

##### AUTH #####

`TokenMiddleware` resolves the `Authorization: Bearer <key>` header once per request into a caller (an account, the admin, or nobody); every route declares its access (`opt=OPT[Access.USER]`) and one guard admits the caller or refuses it. Keys are opaque, kept as a digest in Postgres (`providers/drivers/auth/postgres`), handed out once by the admin (`POST /auth/accounts/{name}/token`); the admin's first comes from `AUTH_SECRET=… python -m e_api admin`.

The MCP door (`src/e_api/mcp/`) serves the same resources to agents at `/mcp` under the same keys and the same refusals: each tool a Litestar route, twin of `api/router/<resource>.py`, reached through the official SDK by one engine (`infra/mcp`).

`make` alone lists every target.
