# e-graph

**e-stack** graph system template: a **React Flow** canvas draws the graph, **rustworkx** analyses its
topology, **LangGraph** runs it — served by Litestar + Granian + msgspec on uv.
The common modules (`engines/`, `infra/`, `ops/`, `ports/`, `processors/`, `providers/`) live once in `../common` and are materialized here by `make common`.

##### LAYOUT #####

```
src/e_graph/
  instrument/    # the LangGraph layer: InstrumentGraph, InstrumentNode, RunState, ui projection, models
  pipelines/base.py                              # PipelineBuilder (compose → build) + PipelineRegistry (sweeps the folders)
  pipelines/<pipeline>/graph.py                  # one <Pipeline>Graph: the wiring (doc, filing)
  pipelines/<pipeline>/nodes/<section>/node.py   # one node per section: runs its specs through the orchestrator
  logic/         # the DARTS engine: agent, models, rules, discover, orchestrator/{core,plan,fusion}
  specs/<pipeline>/<section>/<PFX>-<words>.yaml  # one spec per file; wiki/ shared and per pipeline
  runners/owned/<pipeline>/<section>/<name>.py   # a pipeline section's runners: one role function each
  runners/agnostic/<capability>/<name>.py        # tools any spec may plug
  cli.py         # e-graph darts check | plan — the DARTS static check
  api/           # lifespans, deps, routers: /api/pipelines/*, /api/ui, the canvas at /
  ui/            # the canvas (React Flow, TypeScript) — part of the package; built into ui/dist, served at /
  models/        # section taxonomy, run request, pipeline listing, ui view
src/engines/ infra/ ops/ ports/ processors/ providers/  # GENERATED by `make common` from projects/python/common — edit there, never here
tests/unit/    # mirrors src, import-mode=importlib
```

##### INSTRUMENT #####

```
add_node(node_extract) ─▶ contract check ─▶ InstrumentNode (a real LangGraph StateNodeSpec)
compile() at boot ─▶ topology() (rustworkx: loops by DFS back edges, ranks by generations, lanes by barycenter)
LangGraph ─▶ graph bridge ─▶ node.run(RunState) ─▶ NodeOutput (RUNNING · span + LatencyWrapper · SUCCEEDED | FAILED)
```

Two contracts, one per side:

- **the function** — `async def node_<name>(state: RunState) -> str | dict | NodeOutput | None` in
  `pipelines/<pipeline>/nodes/<category>/node.py`, checked at declaration; a pipeline's graph mounts only its
  own nodes, one per section. A sentence becomes the summary; a dict or a
  `NodeOutput` fills the output's empty slots, unknown keys land in `extra`; `None` falls back to the
  docstring headline. Workflow data lives in `state.context` (`context.<id>`), released when the run
  closes unless `run(state, retain=True)` — the run span keeps its snapshot. Singletons live in
  the system's branches, read under the same names: `state.infra` (`providers`, `engines`, `processors`, `graphs`),
  `state.logic` (`agent`, `orchestrator`), `state.instrument` (`telemetry`, `contexts`). A node that calls the agent reports its `usage`.
- **the node** — `InstrumentNode.run(state) -> NodeOutput`, always: a raise never escapes, it becomes the
  FAILED output (traceback in the log, error recorded on the span). The graph alone speaks LangGraph's
  channels: it hands the RunState over, appends the output, and turns a FAILED output into the
  `NodeError` that stops (or, per `RetryPolicy`, retries) the run — whose verdict is a `RunEnd`.

Routers read the RunState and must name their targets (`Literal[...]` or `path_map`), so the topology
is always total. Every node carries a `role` — `start` (wired from LangGraph's START), `end` (leading
into END; END wins a tie) or `mid` — stamped at compile from the edges themselves, and spelled on every
`NodeOutput` and topology node: the sentinels are never vertices, the role says where they are. Telemetry is the common `providers/drivers/otel.py` (`OTEL_ENDPOINT`), fixed at `state.infra.providers.telemetry`.

##### PIPELINES #####

```python
class DocGraph(PipelineBuilder):
    """Document intake: ingest → (normalize ∥ classify) → extract ⇄ validate → transform → report."""

    def compose(self, graph: InstrumentGraph) -> InstrumentGraph:
        return graph.add_node(node_ingest).add_node(node_normalize)...add_edge("report", END)


async def node_extract(state: RunState) -> dict[str, Any]:
    """Pull the amount out of the canonical text."""
    return await state.logic.orchestrator.node(Section.EXTRACT, state)
```

A pipeline is a folder: `graph.py` declares nodes and edges on the fresh graph it is handed; `build` names
it after the folder, compiles it and returns the built graph. Each node runs its section's specs through the
DARTS orchestrator — see `docs/darts.md` for the taxonomy, the laws and the procedures. The registry sweeps
`pipelines/` at boot — drop a folder, it is served, nothing to import — and the built graphs live once in
`system.infra.graphs`: singletons like the providers; each run is the factory, the graph is shared.

| Pipeline | Sections |
|---|---|
| `doc` | ingest → (normalize ∥ classify) → extract ⇄ validate → transform → report — the demo, every graph shape |
| `filing` | ingest → extract → audit → report — a 10-K read into its XBRL facts, three semantic specs in one call |
| `note` | ingest → extract → inference → audit → report — the 424B2 autocallable family: two issuers (BofA index-linked, Barclays single-stock unguaranteed with memory coupons) read by one 46-spec pipeline held to curated truth; ten fused calls per run |

```bash
e-graph darts check [--pipeline doc] [--json]   # every DARTS law: exit 0 clean, 1 broken — what DARTSOPS runs
e-graph darts plan filing extract               # a section's steps and fused calls, without running it
e-graph lab graph filing extract --draw svg     # a section's spec-graph: tree, dot or svg
e-graph lab simulate filing extract --data source=…/aapl-10k-2025.pdf --out sim/   # every agent call, whole
```

##### API #####

```
GET  /api/pipelines/list             every pipeline under pipelines/: id (its folder name), summary, nodes
GET  /api/pipelines/topology/{id}    the declared graph as a client-agnostic map: nodes by rank/lane/role, arcs
POST /api/pipelines/batch/{id}       one run to completion: terminal NodeOutputs + RunEnd
WS   /api/pipelines/stream/{id}      one run live: send {"data": {...}}, receive every frame, then close
GET  /api/specs/list                         every mounted section: specs, steps, planned agent calls
GET  /api/specs/topology/{id}/{section}      a section's spec-graph placed for drawing: specs by step/lane, arcs, calls
GET  /api/specs/svg/{id}/{section}           the same, drawn: rustworkx DOT → Graphviz on wasmtime
POST /api/specs/simulate/{id}/{section}      rehearse up to the section: every run, the agent calls whole
GET  /api/ui                         the canvas tunables (UI_TOAST, UI_PACE, UI_LANE_GAP, UI_RANK_GAP)
```

##### RUNNING FROM THE CANVAS #####

Every pipeline ships a **default seed** — the run data it expects — declared by its builder
(`seed` on `PipelineBuilder`) and served in `/api/pipelines/list`. The canvas loads it when you
pick the pipeline: select `note`, and the data box already holds its document. **Run works out of
the box; nothing to paste.**

| Pipeline | Default seed |
|---|---|
| `doc` | `{"document":"invoice 8 total 2.50"}` |
| `filing` | `{"source":"tests/resources/documents/filings/aapl-10k-2025.pdf"}` |
| `note` | `{"source":"tests/resources/documents/notes/bofa-autocall-2027.pdf"}` |

The paths are relative to the project root — where `make serve` runs. The data box is yours to
edit: it saves per pipeline on every keystroke (`localStorage`, per origin — `localhost` and
`127.0.0.1` are different storages) and survives the specs tab and pipeline switches. `run`
refuses client-side when the seed loses a key the pipeline declares, naming what is missing
without sending a doomed request; a pipeline with no seed never blocks.

OpenAPI docs come with the server, as `DOCS_*` settings declare them: Swagger at `/docs` (also
`/docs/redoc`, `/docs/elements`, `/docs/rapidoc`), the raw spec at `/docs/openapi.json`, and `/schema`
as an alias — every `/schema/...` answers 307 to the same `/docs/...`. The websocket is not in them —
OpenAPI does not model websockets; its contract is the one above.

##### CANVAS #####

One piece: the canvas lives inside the package (`src/e_graph/ui/`), `make serve` builds it into
`ui/dist/` and starts the server, which serves it at `/` beside the API — http://localhost:8000, no
second process. The bundle ships in the wheel and the image. The canvas speaks the
API exactly as curl would: it picks a pipeline from `list`, lays its `topology` out (rank → row, lane →
centred column), runs it over `stream` — every terminal `NodeOutput` pops a toast bottom-right for
`UI_TOAST` (2.5 s), coloured by status — and pins the `end` node's output (or the failure's) in a card
that stays until closed. A second level, **specs**, opens each node into the spec-graph its orchestrator
runs (a double click on a node gets there): specs by step, fused agent calls as groups, a card per spec, a
rehearsal (`simulate`, rehearsed or against the live model) and every call's payload — instructions,
prompt, schema.

##### DARTSOPS #####

The system keeps itself: a **cyclic maintenance workflow** any coder can load —
`src/e_graph/.coder/workflows/dartsops/` (`workflow.yaml` + one `nodes/<id>.md` per step). It is
interpreted, not executed: the lead agent (opencode, claude, cursor) walks `intake → [loop ≤N:
reproduce → diagnose → craft → gate] → report`, unrolling the bounded loop into finite copies.
The instrument is the CLI:

```bash
make dartsops                     # refresh contract.json, probe the tiers, point at the workflow
e-graph darts contract --json     # the grammar and the 18 laws, as data — what a coder reads first
e-graph darts probe               # is each tier answering, timed (exit 1 if one is asleep)
e-graph darts evaluate <pipeline> --data k=v --expect "spec/field==json" --out signal.json
make dartsops-gate PIPELINE=<p>   # the deterministic wall: laws, plan pins, taxonomy, unit tests
```

`evaluate`'s exit codes drive the loop: **0** green readout, **1** readout signals (spec failures,
*rescued* drift, audits that do not hold, expectations read differently), **2** an unanswered tier —
infra is never patched as if it were a spec. Signals carry kind, address, observed, expected, detail;
the readout JSON is the evidence the report PR carries. Each cassette is self-describing: the request body
pins the endpoint it was recorded against, so replay never depends on the host's `.env`. The laws of craft live in the node bodies:
touch only specs/runners/mirror-tests, never loosen an `output` to silence a signal, truth edits need
the page cited, engine and snapshots are out of bounds. Cost: one live evaluation is one full run —
minutes and real tokens; budget the loop's copies accordingly.

##### TESTS #####

```
tests/unit/        # mirrors src; inputs from tests/resources via pytest-resources (decoded by e-serde)
```

a measured rendering tolerance. Accepting a visual change is a human act: `make snap`, review, commit.

```bash

make check          # lint (ruff + biome) + type (ty + tsc) + arch + validate + drift + test (ui snapshots included)
make snap           # accept the canvas snapshots after a reviewed visual change
make stress         # soak concurrent-load tests
make up             # docker compose up
```
