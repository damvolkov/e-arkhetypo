e-infra

The python infra blueprint of the e-stack template systems: uv · ruff · ty · tach · prek · pytest · zensical.

What this is

Every module a system materializes lives once here — this is the infra blueprint the e-taxis wizard reads when it exports a new project, offering the user the parts that are optional. Services do not depend on this package at runtime: make infra in any system copies the sections of src/e_infra/ into its own src/ (byte-identical except import paths), so each system ships self-contained and this stays the single source of truth. make infra-check fails the moment a copy drifts.

Modules

All sources live under src/e_infra/, layered by tach — high to low: processors -> adapters -> infra -> ops. The purpose of each module is its first docstring line, verbatim; reference pages are generated from the sources: drop a new module under src/ and it appears on the next build.

infra — the project's internal infrastructure

Module Purpose
e_infra.infra.background work that outlives the call that asked for it — one interface over a durable engine or memory.
e_infra.infra.errors typed exception hierarchy — all domain exceptions inherit from CoreError.
e_infra.infra.logger structured JSON in prod, ordered plain text in dev/local.
e_infra.infra.proxy import-safe lazy singletons — the object exists at module level, its load runs on first use.
e_infra.infra.state the app resource graph — dynamic attribute access all the way down.
e_infra.infra.struct msgspec models validated however they are born — decoded at the edge or built in code.
e_infra.infra.settings The dynamic composer — every *Settings of the package, merged into one Settings

infra.settings discovers its scopes on import — adding a scope is dropping a file here:

Scope Purpose

api the HTTP edge of this app — ALLOW_ORIGINS, ALLOW_METHODS.

base pydantic-settings — frozen, typed, layered config.
cli the command-line edge of this app — CLI_TOKEN, CLI_HISTORY.
crypto the configuration of the crypto engine (ops/crypto), loaded from CRYPTO__*.
darts the DARTS orchestrator — how much of a section runs at once, how semantic specs fuse (DARTS_*).
db the embedded sqlite store — DB_PATH.
doc the document processor — which engine reads which page, and how hard to push the deep one (DOC_*).
docling the document-conversion edge — where docling-serve lives and how it converts (DOCLING_*).
docs where the OpenAPI pages live, which aliases lead there, which renderers serve (DOCS_*).
http the outbound HTTP edge — HTTP_BASE_URL, HTTP_TIMEOUT.
md the anytomd Markdown converter — its PDF and vision capabilities and the ZIP fan-out (MD_*).
oauth the OAuth2 identity provider — name, client, secret and metadata URL.
otel the telemetry edge — where spans go, how, how fast, how many (OTEL_*).
ping how long one adapter's ping may take — PING_TIMEOUT.
postgres the Postgres edge — POSTGRES_DSN, pool and statement limits (POSTGRES_*).

redis the redis edge — REDIS_URL.
theme the house theme — background, corporate hue and ink.

ops — agnostic tools: categories only, the closed registry below

Module Purpose
e_infra.ops.compose discover a stack tree and merge chosen fragments into one parameterized document.
e_infra.ops.crypto everything that needs a key or entropy — keyed ids, bearer tokens, password hashing, JWS/JWE, AEAD.
e_infra.ops.file agnostic discovery over an installed package — modules, classes, functions.
e_infra.ops.image deterministic square-font logos — banner by default, house colors, one rect per stroke.
e_infra.ops.registry static code registry — parse a scope with ast, register every symbol by its path, import nothing.

e_infra.ops.tui HeaderTui — the agnostic retro masthead for any Textual app.
e_infra.ops.wrappers agnostic measuring wrappers — scope a block, read what it cost.

Module Purpose

e_infra.adapters.awa the durable background engine — awa, a Rust Postgres job queue, behind BackgroundPort.
e_infra.adapters.base the implementation base for external services — connect, close, ping, async-context bridge.
e_infra.adapters.docling document conversion on docling-serve — any source in, the DoclingDocument and its renderings out.

e_infra.adapters.otel TelemetryPort over the official OpenTelemetry SDK, exported by OTLP over HTTP or gRPC.
e_infra.adapters.pgqueuer the default durable background engine, PgQueuer on asyncpg, behind BackgroundPort.
e_infra.adapters.ports what consumers (routers, deps, lifespan) may ask of an external service.
e_infra.adapters.postgres the SQL edge over psqlpy — a Rust (tokio-postgres) pool, pgvector bound natively.

processors — the document pipeline

Module Purpose
e_infra.processors.doc the DocProcessor — every page read by the engine that reads it best, as fast as the pair allows.
e_infra.processors.md the MDProcessor — any file to Markdown, detected and rendered by the anytomd engine.
e_infra.processors.models what the processors hand out — a document read, or the Markdown a file becomes, both typed.

Opt-in modules

Not every service takes everything: each service's scripts/materialize.py declares its exclusions, and the e-taxis wizard offers the optional parts at export. A module not listed here rides into every service; e-taxis itself materializes the whole tree (the stack machinery — ops/compose — exists for it).

Module Taken by
ops/tui.py tui
ops/snap.py mcp, tui
ops/compose.py mcp
adapters/postgres.py api, graph
adapters/http.py api, cli, graph, tui

adapters/sqlite.py api, cli, graph, tui
adapters/awa.py, adapters/pgqueuer.py, adapters/queue.py none by default — the background's durable engines are opt-in: a service that runs one drops the exclusion

ops — the closed registry of categories

A module in ops/ names a category — what kind of tool it is, never one particular use of it; file is the reference: everything that tells and reads what a file is. Functions are <category>_<scope>[_<detail>]; classes carry the category as surname. Something new joins an existing category; a new category is a decision, recorded, and only while the count stays at 20 or fewer. tests/unit/test_ops_contract.py enforces the three rules against this table.

hash and crypto never overlap: hash takes no key and no secret (it names things); crypto needs a key or entropy (it protects things).

Category Holds Never
algorithm algorithms no domain owns: MinHash/LSH, statistics, numeric normalization anything with a key or a secret — that is crypto
compose stack documents discovered and merged under the compose-go rules deployment; running services
crypto everything that needs a key or entropy: keyed ids, bearer tokens, password hashing, JWS/JWE, signatures, AES-256-GCM hashing without a key — that is hash
file what a file is: detection, import-based discovery over an installed package static code reading — that is registry; structured content — that is parser
hash hashing without a key or a secret: content addresses, every id a project mints anything that needs a key or entropy — that is crypto
image images drawn by rule: the house wordmarks and logos, deterministic SVG raster or photo editing; terminal widgets — that is tui
lexical text read and rewritten by rule: name keys, secret redaction, language identification typed value extraction — that is pattern
parser structured formats read into values: Markdown events, records across versions, the bearer header rewriting text — that is lexical
pattern typed tokens in text, validated and normalized: dates, amounts, identifiers, URLs the meaning of words — that is lexical
registry static code registry: symbols by path through ast, importing nothing import-based runtime discovery — that is file
snap snapshot galleries: the visual drift gate over sets of widgets unit assertions
tui agnostic terminal widgets: the masthead and its kin application screens; domain widgets
wrappers measuring wrappers: scope a block, read what it cost (latency) retry or timeout policy; domain logic

Thirteen categories are claimed of the twenty allowed; a new one is a recorded decision while the limit holds.

Usage

make install      # sync deps + git hooks
make check        # lint + type + arch + validate + test
make cov          # coverage gate (>=90%)
make docs         # serve docs at :8000

Editing rule: src/e_infra/ and the shared root files change here; systems re-materialize. make infra-check in any system fails when its copies drift.
