background

e_infra.infra.background

infra/background: work that outlives the call that asked for it — one interface over a durable engine or memory.

A work is registered once by kind, on a queue, and submitted by kwargs: await background.submit("annotate", documents=(...), force=True) answers at once with the job, queued. The work receives those kwargs and a reporter: each snapshot it reports (plain builtins) becomes the job's progress, written at most every throttle seconds and always once more when the work ends. A work that returns completes its job; one that raises is retried until its attempts are spent; a cancel interrupts it where it awaits.

The engine is a BackgroundPort: a durable one (the awa adapter: Postgres, survives restarts, rescues crashed workers) or MemoryBackground (a task group in this process; nothing survives it). Background always holds the memory engine and prefers the durable one: an engine absent, unreachable on entry, or failing one enqueue sends the work to memory with a warning, never a crash. A durable engine reports an outage as BackgroundError; any other error is the caller's and propagates. Ids are strings, an engine's own, so a lookup asks memory first, then the durable.

BackgroundPort

Bases: Protocol

An engine: register binds a kind to its handler on a queue before start runs slots workers per queue; a handler that returns completes its job, one that raises retries it until attempts are spent. job, jobs and cancel read and settle what is held; an unknown id is None. connect and close bound its life; ping raises when it does not answer.
